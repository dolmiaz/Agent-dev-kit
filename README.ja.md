# Agent-Dev-Kit

[English Version](README.md)

Agent-Dev-Kitは、クラウド環境で動作するコーディングエージェント向けに、環境構築、実行時サポート、作業ログ収集、Issue・PRレビュー連携、スキル同期、および公開ゲート機能を提供する開発ツールキットです。

## 対象環境と適用範囲

- **対象環境:** Codex Cloud および Claude Code on the web
- **適用範囲:** セットアップ、依存関係の検査、リポジトリ固有アイデンティティ設定、作業ログ記録、Issue管理、スキルの配布、および出版セキュリティゲートをサポートします。構成管理やログ収集のためのローカル補助スクリプトが含まれています。
- **対象外:** Codex Legacy、ローカルのコーディングエージェントCLI、および Remote Control のセットアップには対応していません。

## 主な機能

### 1. インストール・更新・削除
- `install.py` は、共通ツール（`.agent-kit/` 以下）、サービス固有のフックや指示ファイル、エージェントスキル、およびオプションのGitHubテンプレート（`--github-templates`）をインストールします。
- `--dry-run`, `--only codex`, `--only claude`, `--uninstall` などのオプションをサポートします。
- マニフェストファイルで管理対象ファイルを記録します。ユーザーが変更したファイルを保護するため、バックアップはターゲットリポジトリの外に作成されます。
- 変更適用前に、安全でないシンボリックリンクやマニフェスト外のパスを検証し拒否します。
- `--profile <file>` による設定読み込みは、プロファイル内の `AGENT_` 形式の設定行を解析し、`.agent-kit/config.env` へ統合（既存値の置換または新規キーの追加）します。`.agent-kit/config.env` は通常Git管理されるため、秘密情報を含めてはなりません。

### 2. 設定および実行時サポート
- 実行環境とサービスを検出し、非秘密の `AGENT_` 設定を読み込み、チェックアウト固有の状態管理、入力のフィンガープリント作成、ロック処理、タイムアウト、およびリトライ制御を提供します。
- **通常設定の優先順位:** 環境変数 > `.agent-kit/config.env` > デフォルト値
- **出版ゲート設定の優先順位:** 環境変数 > `~/.config/agent-kit/publish.env` > `.agent-kit/config.env` > デフォルト値（ユーザーローカルの `publish.env` には非秘密の出版設定のみを保持し、APIキー等の秘密情報は保持しません）。

### 3. 依存関係の準備と検査
- `setup-deps.sh` は Node.js, Python, Go, Rust, Ruby, PHP, Gradle, Maven プロジェクトに対して `deps`, `extras`, `all`, `check`, `plan` サブコマンドを提供します。
- サポートされている環境では、ロックファイル等を尊重した固定バージョンでインストールを行います。ロックファイルの書き換えは行わず、非ロック状態の未サポート構成はスキップします。
- 再実行時は、入力フィンガープリントとインストール済み成果物の両方を検査してスキップ判定を行います。Playwright 関連は検出時または明示的な要求時のみインストールされます。
- `check` および `plan` はパッケージのインストールを行わずに依存関係を検査しますが、共有状態・ロック機構が外部状態ディレクトリやロックファイルを作成・参照するため、完全な読み取り専用ではありません。
- 依存関係処理の失敗時は、厳格モードが指定されない限りデフォルトで非ブロック動作となります。

### 4. オプションのローカルサービス管理
- `services.sh` は、必要なバイナリが存在する場合にローカルの PostgreSQL および Redis サービスの起動・停止・状態表示を行います。
- *注記:* これはローカルプロセスの起動スクリプトであり、クラウド上の管理型データベースサービスを提供するものではありません。

### 5. リポジトリローカルのエージェント識別情報
- `git-identity.sh` は、対象リポジトリに対してローカルスコープでコミット作成者名とメールアドレスを設定します。
- グローバルなGit設定の変更、署名鍵の管理、またはリポジトリへの push 権限付与は行いません。

### 6. エージェント統合とパーミッション
- Codex 向けにセットアップ用エントリーポイントと指示ブロックを提供します。
- Claude 向けに環境セットアップ、セッション開始、ターン開始、停止、ツール実行前フックを提供します。
- サポートされているクラウドコンテキスト内でクラウド権限ルールおよび出版チェックを適用します（ローカルの Claude 環境へクラウド権限を追加するものではありません）。リポジトリ固有の制限が優先されます。各種フックは、全てのツール実行や出版ルートの完全な遮断を保証するものではありません。

### 7. 作業ログの作成と配信
- `agent-log` は `turn`, `sync`, `status`, `show`, `redact` サブコマンドを提供します。
- Markdown 形式で作業ログを作成し、一般的な秘密情報パターンを自動伏字化（リダクト）し、UUIDを付与して、IDおよびコンテンツハッシュにより配信確認を行います。
- 配信失敗時は保留ログをローカルに保持します。ログの送信先および認証情報はユーザー自身が設定する必要があり、サードパーティ製のログ送信先が事前設定されていることはありません。

### 8. 書き込み専用 Drive 受信機能
- Apps Script エンドポイントが、認証された Codex および Claude からの Markdown ログを受け付けます。
- エージェント種別、ファイル名、UUID、メタデータ、ファイルサイズ、コンテンツハッシュを検証します。
- 重複リクエストの制御、拒否フォルダおよび親階層ルールの適用、レート制限・台帳管理・ストレージ容量制限を適用します。
- ユーザー自身によるデプロイ、送信先設定、個別サービスキーの設定が必要です。Google Drive の一般的な読み取り権限付与や Obsidian の自動インストールを行うものではありません。

### 9. Issueの適格性チェックと所有権管理
- `agent-gh` は対象となる GitHub Issue の一覧表示、依存関係チェック、Issueのクレーム（所有宣言）、期限更新、および手放し・引き継ぎ・所有権適用をサポートします。
- クレームとリースタイマーにより重複作業を防止します。ラベルの設定やドラフト PR の作成をサポートします。

### 10. 独立したレビューとマージ判定
- `agent-gh` は固定コミット SHA に対するレビュー記録、モデルおよびセッション実行証拠の検証、ブロック要因の記録、署名付き人間確認の検証を行います。
- ベースブランチの CI ステータス、必須レビュー、マージ可能性ポリシーを評価します。検証不能な証拠をパス（成功）として扱うことはありません。
- マージ準備状態の評価のみを行い、PRの自動マージ自体は実行しません。

### 11. 必須 Gemini 出版ゲート
- `agent-publish` は、管理対象ルートおよび設定された公開ドキュメントパターン（`AGENT_PUBLIC_DOC_GLOBS`）に対する PR のタイトル・本文、リリースノート、公開ドキュメントの更新を制御します。
- 外部送信前にドラフトの事前スキャンを行い、分離された作業ディレクトリ内で設定された Gemini コマンドを実行します。
- 分離構成においてローカル `.env` の自動読み込みおよび CLI ツールを無効化しますが、制限された環境変数アロワリストおよび必要な認証情報（APIキーモードにおける `GEMINI_API_KEY` など）は子プロセスへ明示的に渡されます。
- 出力に含まれるモデル・ツール使用状況、および保護対象コンテンツの検証を行います。ハッシュ記録によりドラフトと最終出力を関連付けます。
- サブコマンドとして `polish`, `retry`, `revise`, `show`/`list`, `reviewed-diff` 確認、ドキュメント適用を提供します。
- 出版の実行には、明示的な設定、認証、利用枠（クォータ）、および検証済み CLI バージョンが必要です。Codex の指示ベース制御や Claude のフック制御は指定ルートを保護しますが、管理外のすべての迂回ルートを技術的に完全に遮断するものではありません。

### 12. スキルインベントリと配布
- `skillsync` は、インベントリ管理、ソースアーカイブへのエクスポート、スキルディレクトリへのセットベースの配置、検証、ロールバック、復元、Zip パッケージ化を提供します。
- マニフェストとロックファイルを維持し、秘密情報を含むコンテンツを拒否し、公開対象チェックを実施します。デフォルトでユーザーのプライベートなスキルコレクション全体を外部配布することはありません。

### 13. パブリックエクスポート検証
- `make-public.sh` は許可リスト（アロワリスト）に基づき、新しいパブリックコピーを作成します。
- `publish-check.py` は、作成されたコピーに対して認証情報、個人情報、許可されていないパス、シンボリックリンク、未検査のバイナリデータをスキャンします。
- 履歴のスキャンは選択可能ですが、Git履歴を含めて公開する場合は必須となります。履歴が取得できない場合や浅いクローン（shallow）の場合は安全のためエラー終了（fail-closed）します。検出された秘密情報は伏字化されます。スキャンを通過したことは絶対的な安全性を保証するものではありません。

### 14. テストとドキュメント
- インストーラの安全テスト、シェル回帰テスト、Apps Script / GitHub / Drive配信 / Gemini 向けのモック検証スイートが含まれています。
- シェルテストスイートは Linux/GNU ツール環境を前提とします。一部のモックはローカル HTTP サーバーを使用します。
- `NO_NET=1` を指定すると外部からの依存関係ダウンロードテストがスキップされますが、テストモックが利用するローカルネットワークループバック通信全般を遮断するものではありません。
- 本プロジェクトは MIT ライセンスの下で提供されており、サードパーティに関する個別の通知が含まれます。

### 実装済みの開発ブランチ追加機能（`main` 未取り込み）

1. **追跡対象の空キーテンプレート**: `.env.sample` に空の `GEMINI_API_KEY=` 設定を含めて明確に追跡管理し、`.env` 自体は除外・未追跡を維持します。
2. **安全なローカルキーランチャー**: `local/with-gemini-env.py` はローカルの `.env` 割り当てを安全に読み込み（権限 600/400 を要求）、プロセス環境経由で `agent-publish` に `GEMINI_API_KEY` を渡します。`--check` フラグは有効な非空キー設定の存在を確認します。
3. **機密情報を漏洩させない Gemini エラーハンドリング**: API 認証情報が応答に含まれる場合は出力を破棄し、生のスタックトレースではなく安全なエラーカテゴリと終了コードを報告します。
4. **ローカルテストの拡充**: ローカル環境およびパブリックエクスポート用のテスト（空／値ありサンプル、削除済み履歴の検証）と CI 構成を追加しました。

## セットアップと使用手順

### インストール手順
1. ドライラン（事前確認）を実行します:
   ```bash
   python3 install.py /path/to/target-repo --dry-run --github-templates
   ```
2. 実際のインストールを実行します:
   ```bash
   python3 install.py /path/to/target-repo --github-templates
   ```

### 非秘密の出版パラメーター設定
環境変数、`~/.config/agent-kit/publish.env`、または `.agent-kit/config.env` に非秘密の設定を記述します:
```env
AGENT_GEMINI_SEND_APPROVED=1
AGENT_GEMINI_AUTH=api-key
AGENT_GEMINI_KEY_ENV=GEMINI_API_KEY
AGENT_GEMINI_MODEL=your-supported-model
AGENT_GEMINI_CLI_VERSION=your-verified-version
AGENT_GEMINI_HOME=/path/to/isolated/gemini-home
```
*注意: これらの設定ファイル内に API キーなどの秘密情報を直接記述しないでください。*

### 出版ワークフローの実行
1. プロセス環境変数に API キーをセットして整形コマンドを実行します:
   ```bash
   # インストール先での実行例:
   python3 .agent-kit/bin/agent-publish polish --kind readme --file README.md --path README.md
   ```
2. 生成されたドラフトの差分を確認し、承認および適用を行います:
   ```bash
   python3 .agent-kit/bin/agent-publish confirm <ID> --reviewed-diff
   python3 .agent-kit/bin/agent-publish apply <ID>
   ```

### 公開用エクスポートのスキャン
1. 新規または空のディレクトリに対して公開用エクスポートを生成します:
   ```bash
   bash tools/make-public.sh /path/to/empty-export-dir
   ```
2. セキュリティスキャンを実行します:
   ```bash
   python3 tools/publish-check.py /path/to/empty-export-dir
   ```
