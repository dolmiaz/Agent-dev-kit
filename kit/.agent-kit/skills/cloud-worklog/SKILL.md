# cloud-worklog — クラウドの作業をターンごとに記録する

クラウドからは Obsidian の Vault に直接書けない。1ターン1ファイルの Markdown を作り、
書き込み専用の受け口(Google Apps Script)経由で Google Drive の決まったフォルダへ送る。
**記録の失敗で作業を止めない。** ローカルで動いているとき(`AGENT_RUNTIME` も `CLAUDE_CODE_REMOTE` も無い)は使わない。

## いつ書くか

ターンの最後、最終返答の直前に1回。Claude Code では、変更があったのに記録が無いと Stop hook が1回だけ促す。

## 書き方

```bash
python3 .agent-kit/bin/agent-log turn \
  --title "短い題(何をしたか。30字程度)" \
  --purpose "このターンの目的(依頼の要約を1〜2文)" \
  --done "実施内容。箇条書き可(- で始める)。なぜそうしたかを1行添える" \
  --tests "実行したテストと結果(例: npm test: 42 passed / pytest -k auth: 1 failed)" \
  --failures "失敗・詰まった点(なければ省略)" \
  --todo "未完了・次にやること・本人の判断が要る点(なければ省略)" \
  --pr "PR の URL(あれば)"
```

長いときは JSON を標準入力で渡せる(`--json -`。キーは同じ名前、値は文字列か文字列の配列)。
自動で入るもの: 日時(JST)、サービス、セッション、ターン番号、UUID、リポジトリ、ブランチ、HEAD、
基点からのコミットと変更ファイル、未コミットの変更、セッション URL(Claude)、セットアップの失敗の有無。

## 守ること

- **秘密を書かない**: トークン・鍵・パスワード・`.env` の値・認証付き URL は書かない。
  ツールも既知の形式を `[REDACTED]` に置き換えるが、それに頼らない。
- **生ログを貼らない**: テスト出力やスタックトレースは要点(失敗したテスト名と1行の原因)だけ。
- **事実だけ**: 実行していないテストを「通った」と書かない。未確認は未確認と書く。
- 作業ログのファイルを編集・削除しない。別サービスのログを送らない(ツールが自動で除外する)。
- 最終返答の末尾に1行で報告する: `📝 作業ログ: <ファイル名>(送信済み)` または `(未送信)`。

## 送れなかったとき(UNSYNCED)

- 未送信のログはリポジトリの外(状態ディレクトリの outbox)に残り、次のターン・次のセッション開始時に
  同じ ID・同じ内容で再送される。**Git にコミットしない**(既定)。
- VM が消えると outbox も消えるため、UNSYNCED のときは最終返答の最後に
  `python3 .agent-kit/bin/agent-log show latest` の出力を `<details>` で添える(会話の記録に残す)。
- 状態の確認: `python3 .agent-kit/bin/agent-log status`。再送: `python3 .agent-kit/bin/agent-log sync`。
