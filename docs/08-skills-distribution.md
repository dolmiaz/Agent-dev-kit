# 個人スキルをクラウド(Codex Cloud・Claude Code on the web)で使えるようにする

## 仕組み

```
手元の個人スキル(例: ~/.codex/skills, ~/.agents/skills, ~/.claude/skills)
   │ skillsync inventory   … 棚卸し(参照資料・スクリプト・CLI・MCP・認証・絶対パス・macOS 専用コマンド・秘密)
   │ skillsync export      … クラウドで動くものだけを正本へ(秘密・巨大ファイル・Mac 専用は拒否)
   ▼
正本(一か所で版管理): 非公開の Git リポジトリ(skills/<name>/、sets.json、checks.json)  ← タグで版を付ける
   │ skillsync vendor --set <セット> --ref <タグ>  … 対象リポジトリへ配る
   ▼
対象リポジトリ
   .agents/skills/<name>/   … Codex Cloud が読む
   .claude/skills/<name>/   … Claude Code on the web が読む
   .agent-kit/skills.lock.json … 正本のコミット・内容ハッシュ・ライセンスと来歴・代表処理(前の版は .prev)
```

### 全部を常に入れない(セット)

スキルの説明文はセッションの文脈に常に入るので、全部を配ると重く、関係のないスキルが選ばれることもある。
正本の `sets.json` にセット(例: `core`・`python`・`writing`・`db`)を決め、リポジトリに合うものだけを配る。

```json
{"sets": {"core": ["minimal-diff", "plan-first-verify"], "python": ["modern-python"], "writing": ["japanese-proofread"]}}
```

`skillsync vendor <正本> <repo> --set core,python --ref v3`。名前を出して頼んだときだけ動くスキル(起動条件のあるもの)は、
起動条件を本文に残したまま配る(配っただけで常に適用されるわけではない)。

### 更新・固定・ロールバック(途中で失敗しても食い違わない)

`vendor`・`rollback`・`remove` は次の順で動く。

1. **全部確認**: 全部の配布先の状態(手で変更されていないか・本人のスキルと同名でないか)、正本の取得、セット名、
   公開リポジトリかどうかを先に調べる。1つでも問題があれば**何も変えずに**止まる。
2. **準備・検証**: 一時領域(`.agent-kit/tmp/`)へ写し、SKILL.md・参照ファイル・スクリプトの構文を検証する。
   rollback は**復元元を全部取得し、lock の内容ハッシュと一致することを確かめてから**次へ進む(今のファイルを先に消さない)。
3. **差し替え**: rename だけでまとめて差し替え、前の内容は一時領域に退避する。失敗したら逆順に戻す。lock は最後に書く。
4. プロセスごと止まった場合は journal(`.agent-kit/skillsync-journal.json`)が残る。次の vendor 等は止まるので、
   `skillsync recover <repo>` を実行する。lock まで書き終えていれば戻さずに片付けだけ、そうでなければ前の状態に戻す。
   一時領域が消されていたら、どこまで進んだか分からないので何も変えずに止まる。
5. 同じ配布先への skillsync は同時に1つだけ(`.git/skillsync.lock`)。中身が同じなら差し替えず、rollback の戻り先(.prev)も変えない。

- **固定**: lock にコミット SHA と内容ハッシュ。`skillsync verify <repo>` で一致・参照ファイル・構文を確認。
- **ロールバック**: `skillsync rollback <repo> --bundle <正本>`。もう一度実行すると戻す前に戻る。それより前は lock を git で戻して vendor。
  `.prev` は配布先のリポジトリにあり書き換えられるので、戻す元は `--bundle` で指定した正本からだけ取る(.prev に書かれた場所は使わない)。
  commit は 40 桁の SHA、内容ハッシュも確かめる。blocked は戻さず、Mac 専用は `--force`、公開リポジトリは `--public-target` とライセンスの確認が要る。
  lock の正本の場所は、ホームを `~` にして記録する。
- **取り外し**: `skillsync remove <repo> --skills a,b`(lock にあるものだけ。配布先のどれかが手で変更されていれば、そのスキルは全部残す)。

### ライセンス・来歴・公開リポジトリ

- vendor は各スキルの `LICENSE*` / `COPYING*` と `UPSTREAM.json` を読み、lock に記録する。
- **正本が非公開でも、公開リポジトリへ配ったスキルは公開される**。配布先が公開リポジトリ(`gh` で確認)か、
  公開か分からない(gh が無い・GitHub 以外)なら `--public-target` が要り、ライセンスで再配布できると分かるもの
  (MIT・Apache-2.0・BSD-2/3-Clause・ISC 等。名前を前後まで照合)だけを配る。分からないものが1つでもあれば、何も配らない。
  非公開と分かっているなら `SKILLSYNC_TARGET_VISIBILITY=private`。
- 上流のあるスキルは、来歴(`UPSTREAM.json`)とライセンスのファイルをパッケージから外さない。

### クラウド向けの書き換え(元のスキルは変えない)

「クラウド向け修正」のスキルは、書き換えの規則(元の文・置き換え後・理由・クラウド用の写しから外すファイル)を
`adaptations.json` に書き、正本に取り込んだ写しにだけ当てる。元の文がちょうど1回見つからなければ止め、写しを捨てる
(元のスキルが変わったら気づける)。書き換えた後の写しを export と同じ検査にもう一度かけ、まだ Mac 専用なら取り込まない。

### 同じ名前のスキルが複数あるとき(make_bundle)

SKILL.md だけでなく、scripts・references・assets を含む**全ファイルの一覧と内容のハッシュ**で比べる。シンボリックリンクは
実体で1つにまとめ、中身が同じものは1つにまとめる。違うものは違うファイルの名前を出して**保留**し、置き場の順では選ばない
(本人が確かめて `--prefer 名前=置き場`)。読めない・空のコピーは「本文を読めていない」として保留する。
3つ以上あるときは、中身ごとの群(例: `A+C / B`)と、それぞれの違うファイルを出す。`--prefer` はどの群の置き場でも選べる。
下位ディレクトリが読めない・ディレクトリへのシンボリックリンクがある場合も、黙って飛ばさずに比べる対象に入れる(読めなければ保留)。
Mac で同じと確かめた記録(same_as)があっても、ここに写しがあればハッシュで比べ直す。

### 正本の commit と版のタグ(make_bundle)

取り込めなかった・保留のスキルがあるときは commit も版のタグも付けない(欠けた版を作らない)。欠けた版でよいときだけ `--allow-partial`。
書き換え規則(adaptations.json)が読めない・形が違うときは、出力先を作る前に止める。
出力先に無関係な変更があれば何もしない。追加するのは今回書いたパスだけ。commit が失敗したら(署名の失敗など)止め、
版のタグは付けない(署名の設定は変えない)。そのとき今回書いたパスは索引も作業ツリーも実行前に戻すので、署名を直したら
そのまま再実行できる。版のタグは注釈付き(`tag.gpgSign` が有効なら本人の設定どおり署名される)。commit の後でタグだけ
失敗したときは、直して再実行すると同じ commit に付ける。一度付けた版のタグは動かさない。同じ操作の再実行は「変更なし」。
中身は同じで判定の記録(`.skillsync.json` の分類)だけが変わったときは、記録だけを更新する。

### claude.ai 用の zip

`skillsync zip` も export と同じ検査(秘密らしいファイル・文字列、サイズ、Mac 専用、参照・構文)を必ず通す。通らなければ
zip を作らない(できかけのファイルも残さない)。秘密らしい文字列は、UTF-8 でないファイルも含めて全ファイルのバイト列で探す。
秘密らしい名前は `.env`・`prod.env`・`.env.local`・`.env.sh`(拡張子で除外しない。`.env.example` 等の見本は除く)、
`*.pem`・`*.key`・`*.p12`・`*.pfx`・`*.ppk`・`*.der`・`*.jks`・`*.keystore`・`id_rsa` 等。出力先がスキルのディレクトリの中なら作らない
(自分自身を梱包しない)。読めない下位ディレクトリがあれば止める(一部だけで梱包しない)。

### スキル名とパス

スキル名は1階層の名前だけ(英数字と . _ -)。`..`・`/`・絶対パス・シンボリックリンクの配布先は扱わない(消さない・書かない)。
リポジトリから配布先までのどの階層も確かめる: `.claude`・`.agents`・その下の `skills`・`.agent-kit`(lock・journal の置き場)の
どれかがシンボリックリンクなら、vendor・remove・rollback・recover・verify は何もしない(リンクの先=範囲の外に書かない・消さない)。
lock に不正な名前・配布先があれば rollback も verify もそれを辿らない。配った写しの中にシンボリックリンクがあれば(copy は
リンクを写さないので、後から置かれたもの)、verify は NG、vendor・remove は「手で変更された」として触らない。
recover は、今の lock が journal の前の lock か新しい lock のどちらかと同じときだけ journal を信用する(v2.3)。
journal は書き換えられうるので、journal だけを根拠にしない: 「前の内容」はディスクの lock のハッシュで判定し、検証済みの退避
(一時領域の退避がディスクの lock の内容と一致)が無い既存の内容は消さない。前の lock に無い・置いた写しと確かめられない内容は、
消さずにリポジトリの外(状態ディレクトリの `skillsync-recover-kept/`)へ移す。lock を書く前に止まった場合は lock・.prev を
書き換えない。lock まで書き終えていた場合も、配布先が新しい lock どおりで、触っていない配布先が新旧の lock で同じで、退避が
journal の前の lock と合うときだけ .prev を更新する(前の lock を確かめられなければ .prev は更新しない)。
どれか1つでも合わなければ、何も変える前に止まる。
`.agent-kit/tmp`・lock・`.prev`・journal がリンクでも何もしない。lock 等は一意な一時ファイル(リンクを辿らない作り方)に書いてから置き換える。
recover は journal のパスが、その配布の一時領域と管理のディレクトリの中だけを指すことを確かめてから使う(書き換えられた journal で外を消さない)。
退避した前の内容が一時領域にも元の場所にも無ければ、「戻した」と言わずに何も変えない。
秘密らしいものを含むスキル(blocked)は `--force` でも配らない(`--force` で配れるのは Mac 専用の判定だけ)。正本がスキルの中にある export はしない。

### 代表処理の確認

正本の `checks.json` に、本人が中身を確認した代表処理のコマンドを書く(例: `{"japanese-proofread": ["python3 scripts/lint.py --help"]}`)。
`skillsync verify <repo> --run --bundle <正本の場所>` が配った各コピーの中でそれだけを実行する。lock は配布先のリポジトリにあり PR で変えられるので、
正本の場所も lock から取らない: **実行する人が `--bundle` で指定した正本**を使い、lock の正本の場所がそれと同じで、commit が 40 桁の SHA で、
その commit の checks.json と同じコマンドのときだけ実行する(どれかが違えば実行せず NG。`--bundle` が無いときも実行しない)。
配った写しは、正本のその commit から写したものとファイル1つまで同じか(`__pycache__`・`node_modules` 等も含めて)を確かめ、
実行は正本から新しく写した一時の写しで行う(配布先のファイルは実行しない)。構文の検査も、配布先のディレクトリのモジュールを読まない(`python3 -I`)。

**限界**: 配布先のリポジトリにある `.agent-kit/bin/skillsync` 自体を書き換えられると、この検査は意味を失う。
`verify --run` は、レビュー済みのブランチ(main)で実行するか、正本や本人の手元のキットにある skillsync で実行する。
レビュー前の PR のブランチで、そのブランチの skillsync を `--run` で動かさない。
中身が lock のハッシュと違うコピーでも実行しない。受け取った ZIP やスキルに含まれるスクリプトを、
確認せずに実行しない(checks.json に書くのは確認した後)。

### コピーしないもの

秘密らしいファイル(`.env`・鍵・credentials)、1MB を超えるファイル、シンボリックリンクの先、バックアップ(`*.bak*`)、
ホームディレクトリ全体、人間用の署名鍵。手元の個人資産(画像集・Vault 等)は同梱しない。

### 分類(1件ずつ決める)

| 分類 | 意味 | 例 |
|---|---|---|
| そのまま利用 | 参照資料・標準的な CLI だけ | 作業規律、言語別の参照 |
| クラウド向け修正 | 保存先・CLI・MCP・個人パスを直せば使える | 保存先が Vault の調査スキル、TeX が要る文書スキル |
| Macへ引継ぎ | 手元のファイル・アプリ・ハードウェアが要る | Downloads の整理、Apple Silicon の計測、Vault の参照 |
| 今回不要 | ホストが同梱しているもの・別用途 | claude.ai / Codex が同梱するスキル、演習専用のスキル |
| 未確認 | 本文を読めていない・材料が足りない | — |

`skillsync inventory` の自動分類(cloud-ok / adapt / mac-only / blocked / skip)は目安。名前があることと本文を読めたことは分けて記録する。
ディレクトリ名と frontmatter の `name` が違うスキル、同じスキルへのシンボリックリンク、同名の別コピーを区別する
(同名の別コピーを確かめずに上書きしない。SKILL.md が同じでも補助ファイルまで同じとは限らない)。

### Macへ引継ぐスキルの扱い

クラウドでは使えないと SKILL.md の外(正本の README・この表)に明記し、配らない。必要な結果は依頼側(Mac の常駐エージェント・本人)が
Issue の「背景」に書く。

## 両クラウドでの確認(配った後に行う)

1. **認識**: Claude は「使えるスキルの一覧を見せて」、Codex は「`.agents/skills` のスキル名を一覧して、どれが使えるか答えて」。
2. **参照ファイルの読み取り**: 例「<スキル> の references/<ファイル> の見出しを3つ挙げて」。
3. **代表的な処理**: 「`python3 .agent-kit/bin/skillsync verify . --run --bundle <正本の場所>` を実行して結果を見せて」(lock に記録した、本人が確認済みの代表処理だけが動く)。
4. 結果を作業ログに残す。モックや手元での成功とは分けて記録する。
